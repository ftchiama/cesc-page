Alterações na secção Inscrições (Secretaria)

1. O que já funciona (não muda)

A secção #seccao-inscricoes já tem:

· Lista com filtros (estado, classe) e ordenação (data, média, idade, nome).
· Detalhe ao clicar em "Ver": dados do candidato, média, documentos (com links assinados), histórico de alterações do candidato.
· Bloqueio de análise: ao abrir uma inscrição, chama cesc_secretaria_iniciar_analise; ao fechar, cesc_secretaria_terminar_analise. O candidato fica bloqueado.
· Aprovar / Rejeitar: modais com motivo e código (0 ou 1).
· Badges de estado: pendente, aprovada, rejeitada, em análise, cód. 0/1.

2. O que precisa de mudar

2.1. Nomenclatura: "Turma" → "Sala"

Na lista de inscrições, a coluna "Turma" deve ser "Sala" (ou removida, se a inscrição ainda não tiver sala). A inscrição é uma candidatura — não tem sala até o AURA distribuir. Portanto, na lista de inscrições, a sala deve aparecer como "—" (vazia) para inscrições pendente/aprovada, e preenchida para as que já foram distribuídas.

2.2. Estado da inscrição vs. estado da matrícula

A lista de inscrições deve mostrar o estado da inscrição (pendente, aprovada, rejeitada, matricula_paga, matriculado), não o estado da matrícula. A inscrição é o registo da candidatura; a matrícula é o registo da situação escolar.

O que mostrar na lista:

· Referência.
· Candidato (nome + BI).
· Classe pretendida.
· Média.
· Data de submissão.
· Estado da inscrição (badge).
· Ações: "Ver".

2.3. O detalhe da inscrição deve mostrar a sala (se já distribuída)

No detalhe (ao clicar em "Ver"), para inscrições matricula_paga ou matriculado, deve aparecer uma secção "Situação Escolar" com:

· Sala.
· Pavilhão.
· Turno.
· Nº de aluno.

Para inscrições pendente/aprovada/rejeitada, a "Situação Escolar" não aparece (porque ainda não há matrícula ativa).

2.4. Filtros de estado: adicionar matricula_paga e matriculado

O filtro #filtro-inscricoes-estado deve incluir:

· Todos os estados.
· Pendentes.
· Aprovadas.
· Rejeitadas.
· Matrícula Paga (novo).
· Matriculado (novo).

2.5. Badges de estado: adicionar matricula_paga e matriculado

Os badges de estado devem incluir:

· badge-pendente — amarelo.
· badge-aprovada — verde.
· badge-rejeitada — vermelho.
· badge-matricula_paga — azul.
· badge-matriculado — verde-escuro.

(Os estilos CSS para estes badges devem ser criados no secretaria.css.)

2.6. Botão "Atribuir Turma" (ou "Atribuir Sala")

Para inscrições matricula_paga, o detalhe deve ter um botão "Atribuir Sala" que:

· Abre o modal.
· Pede a sala (dropdown com as salas disponíveis para o turno do aluno).
· Chama a RPC cesc_secretaria_atribuir_turma (ou uma nova RPC cesc_secretaria_atribuir_sala).
· Muda o estado da inscrição para matriculado.

Nota: este botão é um paliativo até o AURA distribuir automaticamente. No futuro, o AURA faz isto sozinho.

2.7. Auditoria: quem aprovou/rejeitou

O detalhe da inscrição deve mostrar:

· Data da decisão (data_decisao).

· O bloqueio de análise (iniciar_analise / terminar_analise) continua igual.

CREATE OR REPLACE FUNCTION cesc.cesc_secretaria_listar_anos_inscricoes(p_token varchar)
RETURNS json AS $$
DECLARE v_user cesc.utilizadores; v_lista json;
BEGIN
    v_user := cesc.validar_sessao_role(p_token, ARRAY['secretaria', 'diretor', 'sub_diretor']);
    IF v_user IS NULL THEN RETURN json_build_object('ok', false, 'erro', 'Não autorizado.'); END IF;

    SELECT json_agg(ano ORDER BY ano DESC) INTO v_lista
    FROM (SELECT DISTINCT ano_lectivo AS ano FROM cesc.inscricoes) sub;

    RETURN json_build_object('ok', true, 'anos', COALESCE(v_lista, '[]'::json));
END;
$$ LANGUAGE plpgsql SECURITY DEFINER;

CREATE OR REPLACE FUNCTION public.cesc_secretaria_listar_anos_inscricoes(p_token varchar)
RETURNS json AS $$ BEGIN RETURN cesc.cesc_secretaria_listar_anos_inscricoes(p_token); END; $$ LANGUAGE plpgsql SECURITY DEFINER;
GRANT EXECUTE ON FUNCTION public.cesc_secretaria_listar_anos_inscricoes TO anon, authenticated;

CREATE OR REPLACE FUNCTION cesc.cesc_secretaria_stats_inscricoes(
    p_token varchar,
    p_ano_lectivo varchar
)
RETURNS json AS $$
DECLARE
    v_user cesc.utilizadores;
    v_total int;
    v_aprovadas int;
    v_por_aprovar int;
    v_rejeitadas_c0 int;
    v_rejeitadas_c1 int;
BEGIN
    v_user := cesc.validar_sessao_role(p_token, ARRAY['secretaria', 'diretor', 'sub_diretor']);
    IF v_user IS NULL THEN RETURN json_build_object('ok', false, 'erro', 'Não autorizado.'); END IF;

    SELECT count(*) INTO v_total
    FROM cesc.inscricoes
    WHERE ano_lectivo = p_ano_lectivo;

    SELECT count(*) INTO v_aprovadas
    FROM cesc.inscricoes
    WHERE ano_lectivo = p_ano_lectivo
      AND estado IN ('aprovada', 'matricula_paga', 'matriculado');

    SELECT count(*) INTO v_por_aprovar
    FROM cesc.inscricoes
    WHERE ano_lectivo = p_ano_lectivo
      AND estado = 'pendente';

    SELECT count(*) INTO v_rejeitadas_c0
    FROM cesc.inscricoes
    WHERE ano_lectivo = p_ano_lectivo
      AND estado = 'rejeitada'
      AND codigo_rejeicao = 0;

    SELECT count(*) INTO v_rejeitadas_c1
    FROM cesc.inscricoes
    WHERE ano_lectivo = p_ano_lectivo
      AND estado = 'rejeitada'
      AND codigo_rejeicao = 1;

    RETURN json_build_object(
        'ok', true,
        'total', v_total,
        'aprovadas', v_aprovadas,
        'por_aprovar', v_por_aprovar,
        'rejeitadas_c0', v_rejeitadas_c0,
        'rejeitadas_c1', v_rejeitadas_c1
    );
END;
$$ LANGUAGE plpgsql SECURITY DEFINER;

CREATE OR REPLACE FUNCTION public.cesc_secretaria_stats_inscricoes(p_token varchar, p_ano_lectivo varchar)
RETURNS json AS $$ BEGIN RETURN cesc.cesc_secretaria_stats_inscricoes(p_token, p_ano_lectivo); END; $$ LANGUAGE plpgsql SECURITY DEFINER;
GRANT EXECUTE ON FUNCTION public.cesc_secretaria_stats_inscricoes(varchar, varchar) TO anon, authenticated;

Passo 3: RPC da lista de inscrições (ajustada)

```sql
DROP FUNCTION IF EXISTS cesc.cesc_secretaria_listar_inscricoes(varchar, varchar, varchar, varchar, varchar) CASCADE;
DROP FUNCTION IF EXISTS public.cesc_secretaria_listar_inscricoes(varchar, varchar, varchar, varchar, varchar) CASCADE;

CREATE OR REPLACE FUNCTION cesc.cesc_secretaria_listar_inscricoes(
    p_token varchar,
    p_ano_lectivo varchar,
    p_estado varchar DEFAULT NULL,
    p_classe varchar DEFAULT NULL,
    p_ordenar_por varchar DEFAULT 'data',
    p_ordem varchar DEFAULT 'desc'
) RETURNS json AS $$
DECLARE v_user cesc.utilizadores; v_lista json; v_order_sql text; v_query text;
BEGIN
    v_user := cesc.validar_sessao_role(p_token, ARRAY['secretaria', 'diretor', 'sub_diretor']);
    IF v_user IS NULL THEN RETURN json_build_object('ok', false, 'erro', 'Não autorizado.'); END IF;

    IF p_ordenar_por = 'media' THEN v_order_sql := 'media_certificado ' || CASE WHEN p_ordem = 'asc' THEN 'ASC NULLS LAST' ELSE 'DESC NULLS LAST' END;
    ELSIF p_ordenar_por = 'nome' THEN v_order_sql := 'nome_completo ' || CASE WHEN p_ordem = 'asc' THEN 'ASC' ELSE 'DESC' END;
    ELSIF p_ordenar_por = 'idade' THEN v_order_sql := 'data_nascimento ' || CASE WHEN p_ordem = 'asc' THEN 'ASC' ELSE 'DESC' END;
    ELSE v_order_sql := 'data_submissao DESC'; END IF;

    v_query := format('
        SELECT json_agg(json_build_object(
            ''id'', i.id, ''candidato_id'', i.candidato_id, ''referencia'', i.referencia,
            ''nome_completo'', i.nome_completo, ''bi_numero'', i.bi_numero,
            ''data_nascimento'', i.data_nascimento, ''genero'', i.genero,
            ''telefone'', i.telefone, ''email'', i.email,
            ''nome_encarregado'', i.nome_encarregado, ''telefone_encarregado'', i.telefone_encarregado,
            ''classe_pretendida'', i.classe_pretendida, ''curso_pretendido'', i.curso_pretendido,
            ''ano_lectivo'', i.ano_lectivo, ''como_soube'', i.como_soube,
            ''media_certificado'', i.media_certificado,
            ''doc_bi_frente_url'', i.doc_bi_frente_url, ''doc_bi_verso_url'', i.doc_bi_verso_url,
            ''doc_certificado_url'', i.doc_certificado_url, ''doc_foto_url'', i.doc_foto_url,
            ''estado'', i.estado, ''motivo_rejeicao'', i.motivo_rejeicao, ''codigo_rejeicao'', i.codigo_rejeicao,
            ''data_submissao'', i.data_submissao, ''data_decisao'', i.data_decisao,
            ''decidido_por'', (SELECT nome_completo FROM cesc.utilizadores WHERE id = i.decidido_por)
        ) ORDER BY %s)
        FROM cesc.inscricoes i
        WHERE i.ano_lectivo = $1
          AND i.estado <> ''a_pagar''
          AND ($2 IS NULL OR $2 = '''' OR i.estado = $2)
          AND ($3 IS NULL OR $3 = '''' OR i.classe_pretendida = $3)
    ', v_order_sql);

    EXECUTE v_query INTO v_lista USING p_ano_lectivo, p_estado, p_classe;
    RETURN json_build_object('ok', true, 'inscricoes', COALESCE(v_lista, '[]'::json));
END;
$$ LANGUAGE plpgsql SECURITY DEFINER;

CREATE OR REPLACE FUNCTION public.cesc_secretaria_listar_inscricoes(
    p_token varchar, p_ano_lectivo varchar, p_estado varchar DEFAULT NULL, p_classe varchar DEFAULT NULL,
    p_ordenar_por varchar DEFAULT 'data', p_ordem varchar DEFAULT 'desc'
) RETURNS json AS $$
BEGIN
    RETURN cesc.cesc_secretaria_listar_inscricoes(p_token, p_ano_lectivo, p_estado, p_classe, p_ordenar_por, p_ordem);
END;
$$ LANGUAGE plpgsql SECURITY DEFINER;

GRANT EXECUTE ON FUNCTION public.cesc_secretaria_listar_inscricoes TO anon, authenticated;
```

    if (selAno) {
        selAno.innerHTML = "";
        const anos = resAnos.anos || [];
        anos.forEach(function (a) {
            const opt = document.createElement("option");
            opt.value = a;
            opt.textContent = a;
            selAno.appendChild(opt);
        });

        // Selecionar o ano atual (da configuração, se existir)
        const dadosSec = await chamarRPC("cesc_secretaria_dashboard", { p_token: token });
        let anoAtual = null;
        if (dadosSec.ok) {
            // Tentar obter da configuração global
            const cfg = await chamarRPC("cesc_diretor_listar_configuracoes", { p_token: token });
            if (cfg.ok) {
                const item = (cfg.configuracoes || []).find(c => c.chave === "ano_lectivo_actual");
                if (item) anoAtual = item.valor;
            }
        }
        if (anoAtual && anos.includes(anoAtual)) {
            selAno.value = anoAtual;
        } else if (anos.length > 0) {
            selAno.value = anos[0];
        }

        // Ligar o filtro de ano
        selAno.addEventListener("change", function () {
            carregarStatsInscricoes();
            carregarInscricoes();
        });
    }

    configurarFiltrosInscricoes();
    await carregarStatsInscricoes();
    await carregarInscricoes();
}

DROP FUNCTION IF EXISTS public.cesc_secretaria_stats_inscricoes(varchar, varchar) CASCADE;

CREATE OR REPLACE FUNCTION cesc.cesc_secretaria_stats_inscricoes(
    p_token varchar,
    p_ano_lectivo varchar
)
RETURNS json AS $$
DECLARE
    v_user cesc.utilizadores;
    v_total int;
    v_aprovadas int;
    v_por_aprovar int;
    v_matricula_paga int;
    v_rejeitadas_c0 int;
    v_rejeitadas_c1 int;
BEGIN
    v_user := cesc.validar_sessao_role(p_token, ARRAY['secretaria', 'diretor', 'sub_diretor']);
    IF v_user IS NULL THEN RETURN json_build_object('ok', false, 'erro', 'Não autorizado.'); END IF;

    SELECT count(*) INTO v_total
    FROM cesc.inscricoes
    WHERE ano_lectivo = p_ano_lectivo AND estado <> 'a_pagar';

    SELECT count(*) INTO v_aprovadas
    FROM cesc.inscricoes
    WHERE ano_lectivo = p_ano_lectivo AND estado = 'aprovada';

    SELECT count(*) INTO v_por_aprovar
    FROM cesc.inscricoes
    WHERE ano_lectivo = p_ano_lectivo AND estado = 'pendente';

    SELECT count(*) INTO v_matricula_paga
    FROM cesc.inscricoes
    WHERE ano_lectivo = p_ano_lectivo AND estado = 'matricula_paga';

    SELECT count(*) INTO v_rejeitadas_c0
    FROM cesc.inscricoes
    WHERE ano_lectivo = p_ano_lectivo AND estado = 'rejeitada' AND codigo_rejeicao = 0;

    RETURN json_build_object(
        'ok', true,
        'total', v_total,
        'aprovadas', v_aprovadas,
        'por_aprovar', v_por_aprovar,

        'rejeitadas_c1', v_rejeitadas_c1

END;
$$ LANGUAGE plpgsql SECURITY DEFINER;

3. Secção Inscrições só mostra até matricula_paga

A RPC cesc_secretaria_listar_inscricoes deve excluir matriculado da lista (esse estado pertence à secção Matrículas).

Correção na RPC:

```sql
DROP FUNCTION IF EXISTS cesc.cesc_secretaria_listar_inscricoes(varchar, varchar, varchar, varchar, varchar, varchar) CASCADE;
DROP FUNCTION IF EXISTS public.cesc_secretaria_listar_inscricoes(varchar, varchar, varchar, varchar, varchar, varchar) CASCADE;

CREATE OR REPLACE FUNCTION cesc.cesc_secretaria_listar_inscricoes(
    p_token varchar,
    p_ano_lectivo varchar,
    p_estado varchar DEFAULT NULL,
    p_classe varchar DEFAULT NULL,
    p_ordenar_por varchar DEFAULT 'data',
    p_ordem varchar DEFAULT 'desc'
) RETURNS json AS $$
DECLARE v_user cesc.utilizadores; v_lista json; v_order_sql text; v_query text;
BEGIN
    v_user := cesc.validar_sessao_role(p_token, ARRAY['secretaria', 'diretor', 'sub_diretor']);
    IF v_user IS NULL THEN RETURN json_build_object('ok', false, 'erro', 'Não autorizado.'); END IF;

    IF p_ordenar_por = 'media' THEN v_order_sql := 'media_certificado ' || CASE WHEN p_ordem = 'asc' THEN 'ASC NULLS LAST' ELSE 'DESC NULLS LAST' END;
    ELSIF p_ordenar_por = 'nome' THEN v_order_sql := 'nome_completo ' || CASE WHEN p_ordem = 'asc' THEN 'ASC' ELSE 'DESC' END;
    ELSIF p_ordenar_por = 'idade' THEN v_order_sql := 'data_nascimento ' || CASE WHEN p_ordem = 'asc' THEN 'ASC' ELSE 'DESC' END;
    ELSE v_order_sql := 'data_submissao DESC'; END IF;

    v_query := format('
        SELECT json_agg(json_build_object(
            ''id'', i.id, ''candidato_id'', i.candidato_id, ''referencia'', i.referencia,
            ''nome_completo'', i.nome_completo, ''bi_numero'', i.bi_numero,
            ''data_nascimento'', i.data_nascimento, ''genero'', i.genero,
            ''telefone'', i.telefone, ''email'', i.email,
            ''nome_encarregado'', i.nome_encarregado, ''telefone_encarregado'', i.telefone_encarregado,
            ''classe_pretendida'', i.classe_pretendida, ''curso_pretendido'', i.curso_pretendido,
            ''ano_lectivo'', i.ano_lectivo, ''como_soube'', i.como_soube,
            ''media_certificado'', i.media_certificado,
            ''doc_bi_frente_url'', i.doc_bi_frente_url, ''doc_bi_verso_url'', i.doc_bi_verso_url,
            ''doc_certificado_url'', i.doc_certificado_url, ''doc_foto_url'', i.doc_foto_url,
            ''estado'', i.estado, ''motivo_rejeicao'', i.motivo_rejeicao, ''codigo_rejeicao'', i.codigo_rejeicao,
            ''data_submissao'', i.data_submissao, ''data_decisao'', i.data_decisao,
            ''decidido_por'', (SELECT nome_completo FROM cesc.utilizadores WHERE id = i.decidido_por)
        ) ORDER BY %s)
        FROM cesc.inscricoes i
        WHERE i.ano_lectivo = $1
          AND i.estado NOT IN (''a_pagar'', ''matriculado'')
          AND ($2 IS NULL OR $2 = '''' OR i.estado = $2)
          AND ($3 IS NULL OR $3 = '''' OR i.classe_pretendida = $3)
    ', v_order_sql);

    EXECUTE v_query INTO v_lista USING p_ano_lectivo, p_estado, p_classe;
    RETURN json_build_object('ok', true, 'inscricoes', COALESCE(v_lista, '[]'::json));
END;
$$ LANGUAGE plpgsql SECURITY DEFINER;

CREATE OR REPLACE FUNCTION public.cesc_secretaria_listar_inscricoes(
    p_token varchar, p_ano_lectivo varchar, p_estado varchar DEFAULT NULL, p_classe varchar DEFAULT NULL,
    p_ordenar_por varchar DEFAULT 'data', p_ordem varchar DEFAULT 'desc'
) RETURNS json AS $$
BEGIN
    RETURN cesc.cesc_secretaria_listar_inscricoes(p_token, p_ano_lectivo, p_estado, p_classe, p_ordenar_por, p_ordem);
END;
$$ LANGUAGE plpgsql SECURITY DEFINER;

GRANT EXECUTE ON FUNCTION public.cesc_secretaria_listar_inscricoes TO anon, authenticated;
```

Próximo passo: o algoritmo de matrículas

Depois de aplicares estas correções, vamos criar o algoritmo de matrículas. Ele vai:

1. Ler todas as inscrições com estado = 'matricula_paga'.
2. Atribuir sala_id e numero_aluno (com base na alocação).
3. Mudar o estado para matriculado.
4. Criar a matrícula ativa (cesc.matriculas com estado = 'activo').

Isto é o DISTRIBUIDOR do AURA, mas aplicado à secção Matrículas. Na verdade, podemos reusar a RPC cesc_aura_distribuir (que já faz isto) e adicionar uma RPC nova cesc_secretaria_matricular_alunos que:

· Chama o DISTRIBUIDOR.
· Atualiza o estado das inscrições para matriculado.

Queres que eu corrija os 3 pontos acima e depois passemos ao algoritmo de matrículas?
Boa pergunta. Vou esclarecer o ciclo de vida dos estados, porque há uma confusão entre "aprovado" e "matrícula paga".

O ciclo de vida da inscrição (do candidato ao aluno)

Estado O que significa Quem muda
a_pagar Inscrição submetida, mas ainda não pagou a taxa de inscrição (1.000 Kz). Sistema (ao submeter).
pendente Pagou a inscrição. Aguarda análise da secretária. Webhook do pagamento.
aprovada A secretária aprovou os documentos. O candidato ainda não pagou a matrícula (3.000 Kz). Secretária (ao clicar "Aprovar").
rejeitada A secretária rejeitou. Secretária (ao clicar "Rejeitar").
matricula_paga O candidato pagou a matrícula (3.000 Kz). Mas ainda não tem turma/sala. Webhook do pagamento da matrícula.
matriculado A secretária (ou o AURA) atribuiu a turma/sala. O candidato é agora aluno oficial. Secretária (ao atribuir turma) ou AURA (ao distribuir).

O que acontece quando o candidato paga a matrícula?

1. A inscrição está em aprovada (aprovada pela secretária, mas ainda não pagou).
2. O candidato paga os 3.000 Kz.
3. O webhook do AppyPay (ou o mock) chama a RPC cesc_candidato_confirmar_pagamento.
4. Essa RPC muda a inscrição de aprovada para matricula_paga (não para aprovada).
5. O candidato passa a estar matricula_paga, não aprovada.

Portanto:

· aprovada = aprovado, mas ainda não pagou a matrícula.
· matricula_paga = aprovado e já pagou a matrícula, mas ainda não tem turma.

O que a tua pergunta implica:

Tu perguntaste:

"Se alguém é aprovado, paga matrícula, ele subscreve estado aprovado?"

A resposta é: não. Quando paga a matrícula, o estado muda de aprovada para matricula_paga. O aprovada fica para trás (é um estado anterior).

O que os cards devem mostrar (com esta correção):

Aprovadas aprovada (aprovado, mas ainda não pagou).
Por Aprovar pendente.
Matrícula Paga matricula_paga (pagou, mas ainda não tem turma).
Rejeitadas rejeitada (separado por código 0 e 1).

O matriculado não aparece na secção Inscrições (pertence à secção Matrículas).
